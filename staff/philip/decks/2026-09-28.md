# Observation Objective

> Meta goal: Realtime speech to speech (thus minimal latency)
- `e2e_ttft` (end to end time to first token) most critical measurement
- `t/s` (token per second) only needs to slightly exceed natural speech (approx. 5 t/s)
  - aim for `15+ t/s` output generation speed

# Benchmarking

- hardware: `DGX Spark, (RTX 5080 Laptop GPU)`
- backends: `vllm`, `sglang`, `trt-lm`, `atlas`, `llama.cpp`
- client: `llama-benchy`
  - `2048` token prompt
  - `128` token response
  - `0 4096 (8192 16384)` depth
  - `1 2` concurrency

# Observations

- `vLLM` outperforms all other tested inference engines on e2e_ttft
- `NVFP4` quantization aids with e2e_ttft (most likely due to memory bandwidth scaling)
- deeper context (eg. very long system prompts) would move us out of realtime capability relatively quickly
- Gemma 4 Unified (12B) variant at `~370` ms blocks significant amount of realtime budget (500ms e2e)
- default llama-benchy warmup is insufficient (strong fluctuations on first run after startup)

# Factors impacting e2e_ttft

  1. amount of active paramters in model (memory bandwidth)
  2. quantization (memory bandwidth)
  3. prompt length (tokens preprocessed upon request)
  4. depth (preloaded tokens already present in context)
  5. concurrency
